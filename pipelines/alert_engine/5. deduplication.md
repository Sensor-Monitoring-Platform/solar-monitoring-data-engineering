# Part 4 — `deduplication.py`

The purpose of this module is simple:

> **A single physical incident must not create hundreds/thousands of identical alerts.**

For example, suppose:

```text
TEMP-GGN01-L01-MC01-001
```

starts overheating:

```text
10:00:00 → 215°C → CRITICAL
10:00:30 → 218°C → CRITICAL
10:01:00 → 221°C → CRITICAL
10:01:30 → 224°C → CRITICAL
10:02:00 → 226°C → CRITICAL
...
```

Without deduplication:

```text
500 sensor events
       ↓
500 alerts
       ↓
Frontend 💥
Database 💥
Operators 💥
```

Instead:

```text
500 critical events
       ↓
1 OPEN alert
       ↓
events update the existing incident
       ↓
sensor recovers
       ↓
alert RESOLVED
```

# 2. The key concept: Alert Fingerprint

We need a way to answer:

> "Is this new event actually the same incident as an existing alert?"

We should not simply use:

```text
device_id
```

because the same sensor can have different problems.

For example:

```text
TEMP-001 → CRITICAL_HIGH
TEMP-001 → SENSOR_OFFLINE
```

These are different incidents.

So we create an **alert fingerprint**.

For your current architecture, I'd use:

```text
device_id
+
rule_type
+
severity
```

For example:

```text
TEMP-GGN01-L01-MC01-001
CRITICAL_HIGH
CRITICAL
```

becomes one incident.

# 3. `deduplication.py`

Create:

```text
alert_engine/
├── deduplication.py
```

```python
from __future__ import annotations

from dataclasses import dataclass
from datetime import datetime, timedelta
from typing import Dict, Optional


# ============================================================
# DEDUPLICATION RESULT
# ============================================================


@dataclass(frozen=True)
class DeduplicationResult:
    """
    Result returned by the deduplication layer.
    """

    is_duplicate: bool

    fingerprint: str

    existing_alert_id: Optional[str]

    reason: str


# ============================================================
# ALERT DEDUPLICATOR
# ============================================================


class AlertDeduplicator:
    """
    Prevents repeated sensor events from creating duplicate
    alerts for the same underlying incident.

    The deduplicator maintains lightweight in-memory state.

    Permanent alert history belongs to AlertStore.
    """

    def __init__(
        self,
        cooldown_seconds: int = 60,
    ) -> None:

        self.cooldown = timedelta(
            seconds=cooldown_seconds
        )

        # ----------------------------------------------------
        # fingerprint -> alert information
        # ----------------------------------------------------

        self._active_alerts: Dict[
            str,
            AlertDeduplicationState,
        ] = {}

    # ========================================================
    # BUILD FINGERPRINT
    # ========================================================

    @staticmethod
    def build_fingerprint(
        device_id: str,
        rule_type: str,
        severity: str,
    ) -> str:

        return (
            f"{device_id}|"
            f"{rule_type}|"
            f"{severity}"
        )

    # ========================================================
    # CHECK EVENT
    # ========================================================

    def check(
        self,
        device_id: str,
        rule_type: str,
        severity: str,
        event_timestamp: datetime,
    ) -> DeduplicationResult:

        fingerprint = self.build_fingerprint(
            device_id=device_id,
            rule_type=rule_type,
            severity=severity,
        )

        existing = self._active_alerts.get(
            fingerprint
        )

        # ----------------------------------------------------
        # No previous alert
        # ----------------------------------------------------

        if existing is None:

            return DeduplicationResult(
                is_duplicate=False,
                fingerprint=fingerprint,
                existing_alert_id=None,
                reason="NO_EXISTING_ALERT",
            )

        # ----------------------------------------------------
        # Existing alert is already active
        # ----------------------------------------------------

        if existing.active:

            return DeduplicationResult(
                is_duplicate=True,
                fingerprint=fingerprint,
                existing_alert_id=existing.alert_id,
                reason="ACTIVE_ALERT",
            )

        # ----------------------------------------------------
        # Existing alert is inside cooldown period
        # ----------------------------------------------------

        if (
            event_timestamp - existing.last_seen
            < self.cooldown
        ):

            return DeduplicationResult(
                is_duplicate=True,
                fingerprint=fingerprint,
                existing_alert_id=existing.alert_id,
                reason="COOLDOWN",
            )

        # ----------------------------------------------------
        # Cooldown expired
        # ----------------------------------------------------

        return DeduplicationResult(
            is_duplicate=False,
            fingerprint=fingerprint,
            existing_alert_id=None,
            reason="COOLDOWN_EXPIRED",
        )

    # ========================================================
    # REGISTER ALERT
    # ========================================================

    def register(
        self,
        fingerprint: str,
        alert_id: str,
        event_timestamp: datetime,
    ) -> None:

        self._active_alerts[
            fingerprint
        ] = AlertDeduplicationState(

            alert_id=alert_id,

            first_seen=event_timestamp,

            last_seen=event_timestamp,

            active=True,
        )

    # ========================================================
    # UPDATE EXISTING ALERT
    # ========================================================

    def update(
        self,
        fingerprint: str,
        event_timestamp: datetime,
    ) -> None:

        existing = self._active_alerts.get(
            fingerprint
        )

        if existing is None:
            return

        existing.last_seen = event_timestamp

    # ========================================================
    # RESOLVE ALERT
    # ========================================================

    def resolve(
        self,
        fingerprint: str,
        event_timestamp: datetime,
    ) -> None:

        existing = self._active_alerts.get(
            fingerprint
        )

        if existing is None:
            return

        existing.active = False

        existing.last_seen = event_timestamp

    # ========================================================
    # REMOVE
    # ========================================================

    def remove(
        self,
        fingerprint: str,
    ) -> None:

        self._active_alerts.pop(
            fingerprint,
            None,
        )

    # ========================================================
    # GET ACTIVE ALERT
    # ========================================================

    def get_active_alert(
        self,
        fingerprint: str,
    ) -> Optional[str]:

        existing = self._active_alerts.get(
            fingerprint
        )

        if existing is None:
            return None

        if not existing.active:
            return None

        return existing.alert_id

    # ========================================================
    # CLEANUP
    # ========================================================

    def cleanup(
        self,
        now: datetime,
    ) -> None:

        expired = []

        for fingerprint, state in self._active_alerts.items():

            if state.active:
                continue

            if now - state.last_seen > self.cooldown:

                expired.append(fingerprint)

        for fingerprint in expired:

            self._active_alerts.pop(
                fingerprint,
                None,
            )


# ============================================================
# INTERNAL STATE
# ============================================================


@dataclass
class AlertDeduplicationState:

    alert_id: str

    first_seen: datetime

    last_seen: datetime

    active: bool = True
```

# 4. But there's an important design decision

We don't want to deduplicate **everything** using the same rule.

Consider:

```text
TEMP = 211°C
```

then:

```text
TEMP = 250°C
```

then:

```text
TEMP = 300°C
```

It's still the same overheating incident.

So:

```text
CRITICAL_HIGH
```

should remain one incident.

But we may want to **update the existing alert**:

```text
Peak temperature:
211
 ↓
250
 ↓
300
```

The Alert Manager will later maintain:

```text
first_seen
last_seen
current_value
peak_value
occurrence_count
```

So deduplication doesn't mean:

> "ignore subsequent events."

It means:

> **"Don't create another incident; attach the event to the existing incident."**

That's a very important distinction.

# 7. Why we need cooldown after resolution

Imagine this:

```text
10:00 → 220°C
10:01 → 230°C
10:02 → 170°C
10:03 → 220°C
```

If we immediately delete the fingerprint when the sensor recovers:

```text
CRITICAL
   ↓
RESOLVED
   ↓
new CRITICAL
```

we create:

```text
ALERT-001
ALERT-002
```

within a few minutes.

Maybe that's correct — maybe it really is two separate incidents.

But it might actually be a **flapping sensor**.

That's why we maintain a cooldown.

For example:

```text
cooldown = 60 seconds
```

After resolution:

```text
10:02:00 → RESOLVED
```

then:

```text
10:02:30 → same condition
```

can be considered the same incident depending on the policy.

After the cooldown:

```text
10:04:00
```

a new incident may be created.

# 8. One thing I would change later

The current implementation uses:

```text
device_id + rule_type + severity
```

as the fingerprint.

That's good for our first implementation.

But industrial systems often need **incident identity** to be slightly more sophisticated.

For example:

```text
device_id
rule_id
condition
```

is better than relying heavily on severity.

Eventually we should introduce explicit rule IDs:

```yaml
rules:
  - rule_id: TEMP_PROCESS_CRITICAL_HIGH
    sensor_type: temperature_process
    condition: gt
    threshold: 210
    severity: CRITICAL
```

Then the fingerprint becomes:

```text
device_id + rule_id
```

This is cleaner and gives us stable references for:

* alert history
* dashboards
* analytics
* AI evaluation
* rule performance
* false-positive analysis

We'll get there when we improve the metadata model.

# 9. Another important distinction: deduplication vs cooldown

These are often confused.

### Deduplication

```text
Existing incident is OPEN
        ↓
Same event
        ↓
Don't create another alert
```

### Cooldown

```text
Previous incident recently resolved
        ↓
Same condition happens again
        ↓
Wait / suppress according to policy
```

They're different mechanisms.

# 11. What `deduplication.py` deliberately does NOT do

It does **not**:

* evaluate temperature thresholds
* decide whether something is critical
* query the frontend
* write database records
* send WebSocket messages
* decide OPEN/ACKNOWLEDGED/RESOLVED
* perform AI analysis
* determine whether a sensor is physically broken

Those responsibilities belong elsewhere.

This is exactly why we're splitting the engine into components.

                        │

                ┌───────────────┐

                        │

                        │
                        ▼
                ┌───────────────┐
                │   RESOLVED    │
                └───────────────┘

And the key point is that **ACKNOWLEDGED does not mean the machine is safe**.

It only means:

> An operator has seen/taken ownership of the alert.

The sensor condition can still be critical.

That distinction will matter when we implement `alert_manager.py`.
